# On Simplicity

The best software does one thing well. The worst software does everything poorly.

Every feature you add is a promise you're making to maintain it. Every abstraction is a wall between you and the thing you're actually trying to do.

I've been building things for years now and the pattern is always the same: start simple, add complexity, regret it, tear it down, start simple again.

The trick is skipping the middle steps.

## Rules I Try to Follow

· If it works, stop touching it
· If you can't explain it, you don't understand it
· If nobody asked for it, don't build it
· If it takes more than a weekend, break it up

The hard part isn't building things. It's knowing when to stop.
